## 5. 第一批组件的内容设计要点（构建前逐项确认）

### DC-16 乡镇和网点机会优先级
- 教学问题：资源有限时，哪些乡镇/网点最值得优先投入？
- 输入：候选乡镇/网点、增长潜力证据、当前基础、进入/做深难度、配送半径、竞争、负责人
- 学员输出：1-3 个首战对象 + 候补 + 暂缓，每个带一条证据
- 视觉：左侧候选证据卡 → 右侧「经营价值 × 攻坚难度」矩阵 → 底部资源下注区（两阶段优先级画布）
- 核心不变式：价值排序先于难度定位；象限命名固定「优先拿下/重点攻坚/观察验证/暂缓投入」

### DC-06 产品战役增长板
- 教学问题：产品增长来自铺得更广、卖得更动，还是核心品项产出更高？
- 输入：SKU 清单、铺货网点、活跃/回转、SKU 销售、复购、目标品项
- 学员输出：核心品项策略（守/扩/育/淘汰）+ 铺货/动销动作
- 视觉：产品增长驱动板（三杠杆）+ SKU/网点组合矩阵（参考 product-battle.pptx）
- 核心不变式：一次销量 ≠ 爆品；缺回转/复购时用低置信度代理并标注缺失项

### I1 Ask-Then-Reveal 概念页
- 教学问题：先激活经验/暴露判断，再揭示概念（如"国家资源是不是离开县域了？"）
- 输入：问题 + 学员可能判断 + 揭示内容 + 收束
- 学员输出：先表态/判断，再对照揭示
- 视觉：两段式——提问区（问题+选择/表态）与揭示区（讲师控制展示），静态页由讲师控制节奏
- 核心不变式：提问页不得提前出现揭示内容；学员页不出现讲师话术

## 6. 完整链路流程（每个组件源页落地的操作指引，DC-05 已验证）

1. 源页：工作副本上跑构建脚本（**脚本纯 ASCII，中文进 JSON**；色值用模板 theme1 令牌）→ 结构验证 → 入库
2. 槽位合同：`component-slots.json` 追加（replaceable_objects / preserve / 不变式）
3. 预览：`render-component-previews.ps1` 重渲染
4. 图册：`build-component-index.py`（模块/模式/名称映射）→ `build-contact-sheet.py`
5. 注册表：`catalog.json`（+ deck SHA 更新）
6. 文档：decision-component-store 卡片补可执行源页；executable-component-store 组件表
7. 指纹：`build-execution-contract.md` 源 deck SHA/页数更新
