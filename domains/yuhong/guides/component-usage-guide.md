## 2. 六个组件逐个介绍

每个组件按同一格式介绍：**解决什么问题 / 长什么样 / 什么时候用 / 能改哪些内容 / 不能改什么（含容量上限）**。

### DC-01 三个趋势判断（第 1 页）

- **解决什么问题**：回答"县域机会是消失了，还是机会结构发生了变化？"——先让学员表态，再逐条揭示三条趋势判断，追问本地证据。
- **长什么样**：页面上有三条纵向的"变化通道"，每条有判断标签、变化"从……到……"的起点和终点，配数量层级和箭头方向；红蓝绿三色各有语义。
- **什么时候用**：课程开场后的"看趋势"模块，通常 2–4 页组成一组；需要国家方向、市场重心变化、消费决策变化，以及至少一个县域事实或案例作为输入。
- **能改哪些内容**：标题、副标题、三条判断各自的"标签 / 从 / 到"文字、教学提示语（TEACHING_CUE）。
- **不能改什么（容量上限）**：**最多只能放 3 条判断**（`max_items: 3`）。三条纵向通道的排列、数量层级、箭头方向、红-蓝-绿语义色都不能动。换成真实县域数据时，每条判断都要落到经销商的经营影响上，避免变成空泛趋势宣讲。

### DC-02 县域生意版图（第 2 页）

- **解决什么问题**：回答"我的增长空间具体落在哪些县城、已覆盖乡镇和空白薄弱乡镇？"——把守盘区、做深区、开拓区画出来，输出县域生意版图和优先乡镇清单。
- **长什么样**：以县城为中心的经营底图，周边分布乡镇；乡镇用"守盘-做深-开拓"三种动作颜色区分，中心有经营底座层级。
- **什么时候用**：判断完区域状态之后、进入渠道精耕之前；需要行政区域、乡镇清单、网点覆盖、活跃状态、销售或潜力、负责人等输入。
- **能改哪些内容**：标题、副标题、县名、县域证据、4 个乡镇各自的"名称 + 对应动作"、教学提示语。
- **不能改什么（容量上限）**：**最多只能放 4 个乡镇**（`max_items: 4`）。需要 4 个以上乡镇时，按官方规则二选一：① 复制一页继续放；② 把乡镇合并成 4 个区域组。**不要**把标签缩小硬塞成一张密集地图。颜色必须对应经营动作（守盘/做深/开拓），不能只表达销售高低。

### DC-03 四力诊断（第 3 页）

- **解决什么问题**：回答"当前限制县域增长的主短板是品牌力、渠道力、场景力还是产品力？"——围绕一个中心问题，从四个方向做诊断，输出一个主短板、一个次短板及证据。
- **长什么样**：中央一个核心问题，四周四个"诊断透镜"（品牌/渠道/场景/产品），每个透镜有提问和证据两处文字。
- **什么时候用**：趋势和区域状态讲完之后、解决方案模块之前；需要四个维度的定义、症状、证据、评分标准或案例。
- **能改哪些内容**：标题、副标题、核心问题、四个力各自的"提问 + 证据"、教学提示语。
- **不能改什么（容量上限）**：**主短板只能有 1 个，次短板也只能有 1 个**（`max_primary_shortfalls: 1`、`max_secondary_shortfalls: 1`）。四项都低或都高时不能硬评——此时按系统建议取消评分，改为"症状选择 + 证据"诊断。每一"力"必须连接可观测指标，挑战没有证据的自评分。

### DC-04 四阶段成长判断（第 4 页）

- **解决什么问题**：回答"经销商当前卡在进得去、站得住、卖得动还是做得深？"——让学员先选阶段，再揭示判断标准，输出当前阶段和下一阶段通关任务。
- **长什么样**：四级台阶/阶段路径，颜色由浅到深；每级"先结果、后任务"（先写该阶段的结果表现，再写通关任务）。
- **什么时候用**：四力诊断之后、渠道和产品打法之前；需要各阶段定义、进入条件、典型症状、案例或经营指标。
- **能改哪些内容**：标题、副标题、阶段判断规则（STAGE_RULE）、四个阶段各自的"结果 + 任务"、教学提示语。
- **不能改什么（容量上限）**：**四个阶段名称是固定的：进得去、站得住、卖得动、做得深**（`fixed_labels`），不可改名、不可增减。四级台阶结构、阶段顺序、"先结果后任务"逻辑、由浅到深配色都不能动。每阶段只保留一个关键判断和一个通关指标；如果问题实际是并行的，允许"主阶段 + 次级瓶颈"双标签，不要硬塞成线性成熟度。

### DC-17 病症聚类诊断（第 5 页）

- **解决什么问题**：回答"面对大量零散经营问题，真正需要优先解决的主问题是什么？"——先收集可观察症状（禁止直接写原因或方案），再聚类成问题簇，选出一个主问题，输出 3–5 个问题簇、一个主问题、一个待验证原因假设。
- **长什么样**：左侧是"症状墙"（若干症状卡），中间是收敛箭头，右侧是诊断聚类区（若干问题簇）。卡片颜色只表示来源或对象，不表示严重度。
- **什么时候用**：诊断模块开头，进入四力、渠道或产品专项之前；需要现场症状、网点/产品/拜访/服务事实、问题提出人、影响对象、出现频率或严重程度。
- **能改哪些内容**：标题、副标题、8 张症状卡的正文、4 个问题簇各自的"名称 + 描述"、教学提示语。
- **不能改什么（容量上限）**：**最多 8 张症状卡**（`max_symptoms: 8`）、**最多 4 个问题簇**（`max_clusters: 4`）。"先事实后原因"的顺序纪律不能破：症状卡只写可观察症状，主问题必须写成"对象 + 可见表现 + 经营影响"。人少或时间短时，可由讲师预置 8–12 张症状卡（注意：页面上最多放 8 张，多余的卡可留在备选清单里，页面内只放 8 张）。

### DC-20 阶段-病症-四力-动作综合诊断（第 6 页）

- **解决什么问题**：回答"如何把乡镇经营事实完整转化为阶段判断、当前任务、主病症、四力短板和优先动作？"——按固定五步完成一条完整诊断陈述和 2–3 项优先动作。
- **长什么样**：纵向五步"诊断脊柱"：左侧是步骤名，中部是诊断问题，右侧填写输出。
- **什么时候用**：判状态模块的收束页，或综合案例诊断页；需要乡镇经营结果、当前阶段证据、投入与结果不匹配的症状、四力证据、资源约束和候选动作。
- **能改哪些内容**：标题、副标题、案例提示（CASE_PROMPT）、五个步骤各自的"问题 + 输出"、教学提示语。
- **不能改什么（容量上限）**：**五步顺序固定：阶段 → 任务 → 病症 → 四力短板 → 优先动作**（`fixed_order`），不能换序、不能增删步骤。**优先动作最多 3 项**。禁止从病症直接跳到促销或铺货动作；证据不足时保留"待验证"，不进入动作选择。

## 3. 在 PowerPoint 里怎么用（四步）

**原则：只复制、只改文字，绝不重画。** 这套组件的设计规则就是"复制源页 + 编辑命名对象"（`reuse_mode: duplicate-source-slide-and-edit-named-objects`），官方明确禁止重画。

### 第一步：打开组件源 PPT

```
C:\Users\Swefner\OneDrive\Desktop\朴道晟源\pppt\company-ppt-skills\domains\yuhong\assets\components\yuhong-county-course-components-branded.pptx
```

双击用 PowerPoint 打开。文件里有 6 页，就是你需要的 6 个组件。

### 第二步：复制需要的幻灯片

1. 在左侧缩略图栏选中你要的页面（例如第 3 页四力诊断）。
2. 右键 →「复制幻灯片」，或 Ctrl+C / Ctrl+V 到你的目标 PPT。
3. 建议先看一眼对应的预览图（第 4 节有路径），确认布局符合预期再复制。

### 第三步：替换文字内容

1. 在复制进来的页面上，点击要改的文字框，直接改成真实内容（如某县的真实乡镇名、真实的症状描述）。
2. **能改什么**：第 2 节每个组件列出的可替换内容（标题、副标题、判断/证据/问题/输出等文字）。
3. **不能改什么**：页面结构、图形、颜色、箭头、顺序、阶段名，以及上面没列出的任何对象。系统规则要求"未列为可替换的命名对象必须保留原样"（`preserve_named_objects_not_listed_as_replaceable`）。
4. 注意容量上限（第 2 节每条的"不能改什么"）：比如 DC-02 最多 4 个乡镇、DC-17 最多 8 张症状卡。

### 第四步：检查页面

对照以下几点过一遍：

- 文字是否放进了对应的框（不要把"结果"写进"任务"框）。
- 是否超量：乡镇数、判断数、症状卡数、动作数有没有超过上限。
- 页面是否还能被正常编辑（不要合并形状、不要转成图片——组件要保持可编辑）。
- 授课逻辑是否完整：讲师要讲什么、学员要做什么、输出是什么。

## 5. 怎么维护（改过组件之后）

### 预览图册是什么

`component-store-render-sheet.png` 是把 6 张预览图拼成一张的总览图册（3 列 x 2 行，每格带 DC 编号和中文名），供快速对照选择。它是由 `build-contact-sheet.py` 从 `previews\component-01.png` ~ `component-06.png` 拼出来的。

### 组件改过之后如何重新生成预览

只有两种情形需要重新生成：**组件源 PPT 或其母版（模板）改动了**。平时只是复制页面、改文字，**不需要**重跑。

1. 打开 PowerShell，进入组件目录：
   ```
   cd C:\Users\Swefner\OneDrive\Desktop\朴道晟源\pppt\company-ppt-skills\domains\yuhong\assets\components
   ```
2. 运行渲染脚本（需要本机装有 PowerPoint）：
   ```
   .\render-component-previews.ps1
   ```
3. 脚本会重新导出 `previews\component-01.png` ~ `component-06.png`（1280x720），并更新 `previews\component-render-manifest.json`（记录源文件和各预览图的校验码）。
4. 预览图更新后，**再运行一次**图册脚本，让图册与预览图保持一致：
   ```
   python .\build-contact-sheet.py
   ```
   这会重新生成 `previews\component-store-render-sheet.png`。此脚本依赖 Python 的 Pillow 库（PIL），字体取用 Windows 的微软雅黑。
5. 改完后把 `component-slots.json` 里的 `source_deck_sha256` 也更新为新的文件校验码（以脚本输出的校验码为准）。

> 注意：`component-render-manifest.json` 里有一句注释写的是"tools/render-component-previews.ps1"，实际脚本位置是 `assets\components\render-component-previews.ps1`，以本手册和实际文件位置为准。

## 6. 常见问题

### Q1：找不到组件文件
- 确认路径完整：`C:\Users\Swefner\OneDrive\Desktop\朴道晟源\pppt\company-ppt-skills\domains\yuhong\assets\components\yuhong-county-course-components-branded.pptx`。
- 如果这个路径下没有文件，说明仓库不完整或路径被移动过，找系统管理员恢复，**不要**用别处下载的类似 PPT 顶替——组件页与模板母版绑定，换文件可能丢失样式。
- 注意别混淆两份易混文件：`component-store-contact-sheet.png`（另一张验收总览图）与 `previews\component-store-render-sheet.png`（六合一预览图册）名字像但用途不同。

### Q2：想改组件长相（颜色、布局、结构）
- 这是"改组件本身"，不是"用组件"。
- 改完之后必须重新生成预览（第 5 节），并同步更新 `component-slots.json`（可替换对象、容量、不可改项）和 `decision-component-store.md`（业务定义），否则预览图和校验记录会与实际不一致。
- 组件页与母版 `assets\reference-decks\yuhong-template.pptx` 绑定（`master_inheritance_required: true`），改母版同样要重跑渲染。

### Q3：想新增一个组件
- 系统现有 6 个可执行组件，只覆盖这 6 种业务问题（第 2 节）。
- 新增组件需要：在源 PPT 里加页 → 在 `component-slots.json` 里登记（编号、页码、可替换对象、容量、不可改项）→ 在 `decision-component-store.md` 里补业务定义 → 重跑渲染脚本和预览图册脚本。
- 如果只是需要一个"组件式页面"但不在上述 6 种问题里，先查 `decision-component-store.md` 里有没有对应的决策组件定义（该文件里还有 DC-05~DC-08、DC-16、DC-18、DC-19 等只有文字卡、没有可执行幻灯片的组件），再决定是复用、还是登记新组件。以 `decision-component-store.md` 文件为准。

### Q4：想放的内容超过容量上限
- 看第 2 节每个组件的"不能改什么"：例如 DC-02 最多 4 个乡镇（超出就复制页面或合并成 4 个区域组）、DC-17 最多 8 张症状卡和 4 个问题簇、DC-01 最多 3 条判断、DC-03 主/次短板各 1 个、DC-20 优先动作最多 3 项。
- 容量约束来自 `component-slots.json`，超量塞入会被视为不符合组件规范。

### Q5：文字放不下 / 框太小
- 组件是固定版式，不要为了塞字把字号缩小或拖动结构调整。精简文字：页面上只留关键句，计算口径和详细说明放备注或附录。
