# Component Cards

Use the cherry-red logic component library only when it strengthens the business story. Do not add a cool component if a simple table or chart is clearer.

Source deck: `assets/reference-decks/cherry-red-logic-components.pptx`.

## Selection Rules

Select by business question, not by visual style.

Use this priority:

1. The component directly answers a dealer-owner question.
2. The data fields exist or can be clearly labeled as assumptions.
3. The structure does not force a fake causal relationship.
4. The owner can understand the slide within 10 seconds.
5. The component supports the next decision or action.

Avoid components that are pure brand/process/UI language unless the deck is a case story, service flow, or method training deck.

## Component Groups

### A. KPI And Target Review

#### Slide 102: KPI Overview

- Priority: Build.
- Use for: core KPI review opening.
- Answers: is the month good, and where is it good?
- Data: sales, collection, key product/category sales, active customers, new customers, target values, comparison baseline.
- Replace with: central achievement or contribution; side cards for the three most important owner metrics; small charts for target vs actual.
- Risk: too many KPIs weaken the message. Keep to 3-5.

#### Slide 12: Target Achievement Ladder

- Priority: Continue.
- Use for: monthly target achievement.
- Answers: which goals hit, which missed?
- Data: target and actual for sales, collection, key product/category, active customers, new customers.
- Replace with: one goal per row and achievement rate on the right.
- Risk: explains result, not cause. Follow with a driver slide.

#### Slide 69: Five Metric Scorecard

- Priority: Build for diagnostic decks; Continue for monthly reviews.
- Use for: dealer health scorecard or channel/product/member health overview.
- Answers: which 5 indicators define this operating theme?
- Data: metric name, actual value, target/benchmark, short interpretation.
- Replace with: 网点数量、核心店占比、有效门店占比、单店产出、人均服务网点数; or 会员数量、会员活跃率、会员人均产出、专业人士会议、复购.
- Risk: if values are not comparable, do not visually imply equal weight.

#### Slide 103: Problem/Opportunity Cards

- Priority: Go deeper.
- Use for: showing 3 operating problems or opportunity types.
- Answers: what are the main obstacles to the next growth step?
- Data: problem label, affected customer/channel/product, severity, evidence, recommended response.
- Replace with: "有效门店占比不足", "核心店占比偏低", "会员活跃率不足", etc.
- Risk: can become a generic consulting page. Must include concrete evidence.

### B. Growth Drivers And Structure Diagnosis

#### Slide 46: Growth Driver Breakdown

- Priority: Build.
- Use for: sales growth source.
- Answers: did growth come from customers, orders, SKU/product, channel, or key accounts?
- Data: customer count, order count, average output, SKU count, category amount, new/old customer sales.
- Replace with: center as monthly sales growth; branches as customer, order, product, channel.
- Risk: needs detail data. If detail is missing, label as directional.

#### Slide 45: Funnel-To-Action Driver Map

- Priority: Continue.
- Use for: converting one core result into supporting drivers and actions.
- Answers: what smaller levers sit under the main result?
- Data: main KPI, 3-5 subdrivers, action levers, owner notes.
- Replace with: "销售额" -> "网点活跃度 / 单店产出 / 品类数量 / 核心店占比".
- Risk: do not use if the driver relationship is not real.

#### Slide 57: Layered Operating Model

- Priority: Go deeper.
- Use for: explaining a complex operating system, such as channel intensive cultivation or service business.
- Answers: how do strategy, process, customer, and data connect?
- Data: layers, roles, metrics, process steps.
- Replace with: "区域扫描 -> 网点分级 -> 路线拜访 -> 一店一策 -> 月度复盘".
- Risk: too complex for owner monthly review; better for method training.

#### Slide 58: Two-Part Comparison Plus Action List

- Priority: Continue.
- Use for: comparing before/after or current gap vs next action.
- Answers: what changed, and what must be done next?
- Data: before metrics, after/current metrics, action list.
- Replace with: "上月问题/本月结果 + 下月动作清单".
- Risk: not suitable for dense numerical analysis.

### C. Customer, Outlet, Member, And Channel Migration

#### Slide 87: Customer Tier Migration

- Priority: Go deeper.
- Use for: customer structure and depth.
- Answers: are customers moving from low value to active/high value?
- Data: customer-level sales by month, tier rules, SKU count, purchase frequency, key-product purchase.
- Replace with: low-activity -> active/repeat -> key/high-value/deep product customers.
- Risk: cannot be used honestly without customer-level data.

#### Slide 49: Lead/Visit/Order Conversion Funnel

- Priority: Build when visit or service data exists.
- Use for: visit coverage, home-decoration leads, member activation, or work-order conversion.
- Answers: where does execution leak before order conversion?
- Data: leads/targets, visits, accepted follow-up, orders, conversion rate, owner/team handoff.
- Replace with: "拜访客户池 -> 有效沟通 -> 下单客户 -> 复购/加购"; or "工单 -> 勘测 -> 报价 -> 签单".
- Risk: do not use when only final sales data exists.

#### Slide 50: Three-Stage Process Board

- Priority: Continue.
- Use for: decomposing customer operation into 3 phases.
- Answers: where should the team focus in the customer lifecycle?
- Data: stage names, customer counts, actions, blockers.
- Replace with: "开发 -> 激活 -> 做深"; or "注册会员 -> 活跃会员 -> 高价值会员".
- Risk: each stage needs a measurable checkpoint.

#### Slide 76: Decision-To-Purchase Journey

- Priority: Go deeper.
- Use for: C-end, double-package, home-decoration, or service conversion.
- Answers: what actions move a customer from interest to purchase?
- Data: touchpoints, objections, conversion action, decision criteria.
- Replace with: "需求识别 -> 方案报价 -> 施工信任 -> 下单购买".
- Risk: can look like consumer journey; use only for service/retail/home-decoration narratives.

### D. Product, Category, And SKU Deepening

#### Slide 59: Product/SKU Deepening Path

- Priority: Build.
- Use for: key product or explosive product deepening.
- Answers: how to make the product result repeatable next month?
- Data: SKU-level sales, customer penetration, single-SKU vs multi-SKU customers, repeat purchase.
- Replace with: trial purchase -> repeat -> multi-SKU -> key-customer package.
- Risk: needs SKU mapping and customer purchase depth.

#### Slide 54: Value Ladder / Price-Tier Logic

- Priority: Replace for monthly review; Go deeper for product strategy.
- Use for: explaining product ladder, package ladder, or customer value ladder.
- Answers: how do we move customers from low value to higher value?
- Data: product tiers, price/package, customer segment, margin or value proposition.
- Replace with: "基础防水 -> 组合产品 -> 双包服务"; or "单品购买 -> 多品类购买 -> 一站式服务".
- Risk: not useful for performance review without a clear product strategy.

#### Slide 63: Multi-Bubble Category Relation

- Priority: Continue.
- Use for: showing category portfolio or channel-category linkage.
- Answers: which categories or channels reinforce each other?
- Data: category sales, customer overlap, attach rate, strategic role.
- Replace with: waterproofing, mortar, beauty seam, membrane, accessories, service.
- Risk: avoid if the relationship is only visual and not data-backed.

#### Slide 80: Hub-And-Spoke Product Ecosystem

- Priority: Go deeper.
- Use for: showing a core product with surrounding growth levers.
- Answers: which surrounding actions make the core product grow?
- Data: core product, target customer, support SKU, promotion, visit, training, display.
- Replace with: core explosive product at center; surrounding levers as display, meeting, route visit, package, rebate.
- Risk: can become a poster. Include inspection metrics.

### E. Visit, Execution, And Action Planning

#### Slide 111: Visit Effect Curve

- Priority: Replace or Go deeper.
- Use for: visit coverage and conversion effect.
- Answers: did visits produce orders, reactivation, or next actions?
- Data: visit records, customer purchase after visit, unvisited comparison, follow-up result.
- Replace with: visited vs unvisited customer result or before/after visit journey.
- Risk: can look like internet-product journey. Replace with Slide 49 funnel or a table if visit data is weak.

#### Slide 61: Milestone Timeline

- Priority: Continue.
- Use for: action rhythm or monthly campaign timeline.
- Answers: what happened when, and what is next?
- Data: key dates, action names, owner, result.
- Replace with: "月初目标分解 -> 中旬拜访追踪 -> 月末复盘 -> 下月行动".
- Risk: do not use for KPI review; it is about rhythm, not performance.

#### Slide 62: Big Arrow Execution Roadmap

- Priority: Continue.
- Use for: next-month key battle execution roadmap.
- Answers: what sequence should the team follow?
- Data: 4-6 steps, owner, milestone, inspection metric.
- Replace with: "筛选目标网点 -> 路线拜访 -> SKU进店 -> 陈列检查 -> 订单复盘".
- Risk: too process-heavy unless it supports the action plan.

#### Slide 113: Next-Month Action Board

- Priority: Build.
- Use for: next-month management board.
- Answers: what should the owner inspect next month?
- Data: actions, owner, target customer/SKU/channel, due date, inspection metric.
- Replace with: 3-5 actions and measurable check points.
- Risk: original structure is system-like. Simplify for monthly review.

#### Slide 119: Service Workflow Line

- Priority: Go deeper for service/double-package; Replace for ordinary monthly review.
- Use for: service workflow, double-package order process, or home-decoration fulfillment.
- Answers: what steps make service delivery reliable?
- Data: process steps, handoff owner, quality gate, timing.
- Replace with: "需求 -> 勘测 -> 报价 -> 签单 -> 施工 -> 验收".
- Risk: not an operating result page. Use in service method or case deck.

### F. Case Story And Transformation

#### Slide 89: Two-System Transformation Map

- Priority: Go deeper.
- Use for: transformation case where old model changes into new model.
- Answers: what changed from old operating logic to new operating logic?
- Data: old model, new model, bridge actions, result.
- Replace with: "老板个人管理 -> 公司化运营"; or "单一分销 -> 全渠道服务".
- Risk: needs a real transformation story.

#### Slide 90: Innovation/Project Case Hub

- Priority: Continue for case decks.
- Use for: positioning a new project or growth initiative.
- Answers: what is the initiative and what capabilities support it?
- Data: initiative name, key actions, support roles, metrics.
- Replace with: "双包服务项目", "家装公司合作", "乡镇渠道下沉".
- Risk: too abstract unless backed by action pages.

#### Slide 92: Method Landing Framework

- Priority: Go deeper for method/training; Replace for monthly review.
- Use for: showing how a method becomes system, tool, and execution.
- Answers: what are the steps from concept to implementation?
- Data: stage names, outputs, tools, responsible roles.
- Replace with: "目标客户 -> 价值观/原则 -> 设计模式/动作 -> 技术/工具实现" only if building an operating system or training deck.
- Risk: too heavy for owner monthly review.

#### Slide 98: Integrated Diagnosis Map

- Priority: Continue.
- Use for: summary of multi-factor diagnosis.
- Answers: how do several dimensions connect to one management conclusion?
- Data: 3-4 dimensions, each with evidence and action implication.
- Replace with: "分销健康 / 产品结构 / 会员活跃 / 家装增长" around a central conclusion.
- Risk: can become crowded. Use only for synthesis, not first explanation.

### G. Components To Avoid Or Use Rarely

- Slide 54: use only for product/value ladder, not KPI review.
- Slide 64: channel/contact map is too internet-oriented for ordinary dealer review.
- Slide 67: supply-chain/e-commerce flow is usually off-context.
- Slide 92: useful for method training, too dense for owners.
- Slide 112 and Slide 120: brand/experience language; avoid in monthly operating review.
- Slide 115: system architecture; avoid unless building digital platform explanation.

## Card Output Format

When proposing components to the user, output each as:

- Source slide
- Component type
- Business question
- Best deck page
- Required data
- Replacement plan
- Usage risk
- Recommendation: Continue / Go deeper / Replace / Build
