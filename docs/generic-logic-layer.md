# 通用逻辑层（Generic Logic Layer）

> 产品级概念，不绑定任何单一领域。参见 `docs/product-architecture.md` §4。

## 1. 定位

通用逻辑层 = 跨领域可复用的**逻辑表达**（增长拆解、驱动板、矩阵、路径、漏斗、架构等），不属于任何客户。它是产品的"逻辑母版"，领域组件从它派生，但**永远不会直接复制它的页面**。

**现状资产**：`domains/ufs/assets/reference-decks/cherry-red-logic-components.pptx`（141 页，樱桃红风格），可检索索引见 `cherry-red-logic-index.md`（同目录）。

## 2. 三条规则（硬约束）

1. **通用逻辑页不是源页**——不直接复制进任何领域组件库。视觉不兼容（樱桃红 vs 客户母版），且违反品牌继承契约（见 `build-execution-contract.md`）。
2. **它是逻辑参考**——按业务问题挑页，在客户母版上**重建**（照抄逻辑结构、重画视觉、命名槽位）。
3. **决策组件卡片（DC）是桥**——通用层与领域层之间通过 DC 卡片连接：卡片写"解决什么业务问题 + 用什么逻辑结构"，领域层负责"在客户母版上重建 + 槽位化"。

## 3. 工作流（领域组件从通用层派生）

```
1. 按业务问题在 cherry-red-logic-index.md 粗筛（增长拆解/驱动板/矩阵/路径/漏斗/架构）
2. 打开对应页目视精筛（索引只有标题，结构以打开页为准）
3. 定义/更新决策组件卡片：业务问题 + 逻辑结构 + 输入输出（decision-component-store.md）
4. 在客户母版上重建源页（COM 构建流程，见 HANDOFF §5）
5. 槽位合同（component-slots.json）→ 渲染预览（render-component-previews.ps1）→ 索引入库（build-component-index.py）→ 图册（build-contact-sheet.py）
```

## 4. 维护

- **重新扫描**：库文件变更后运行 `scan-cherry-logic.ps1`（同目录）重新提取标题/形状数。
- **重建索引**：扫描后运行 `build-cherry-logic-index.py` 重新生成 `cherry-red-logic-index.md`。
- **分类说明**：索引按标题模式分"装饰模板页 / 业务样例页"两类——装饰页提供通用逻辑图结构，样例页提供带真实内容的示例；两类都可作参考。

## 5. 当前覆盖与缺口

- 已覆盖：装饰逻辑图（35 页）、业务样例（106 页）——矩阵、架构、解决方案、用户/运营逻辑、漏斗/转化、管理/考核等类型齐全。
- 缺口：樱桃库是 UFS 侧的通用图库；未来可考虑按需补充"渠道精耕""产品战役"等业务域的通用逻辑图，或在客户母版上重建时反向沉淀新的通用逻辑页。
