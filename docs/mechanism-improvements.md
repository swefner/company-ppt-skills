# 机制改进清单（PPT 产品 ← 客户分析产品）

> 客户分析产品（`客户分析技能包/`，v1.4.1）与方法论同源但部分机制更成熟。本清单记录 PPT 产品应借鉴的三项机制及落地草案。来源均已在客户分析产品中实测打磨（版本日志逐条对应豆包实测失败模式）。

## 1. 公司档案机制（用户级沉淀）

**客户分析的做法**：
- 首次使用结束时 AI 自动生成《公司档案》（字段映射、清洗规则、实体归并决定、公司信息、使用习惯），用户确认后保存；
- 再次使用：档案 + 数据特征指纹核对（表头位置/列数/日期格式/关键列名）→ 指纹一致则直接沿用配置，只问 1 个问题；
- 档案只追加不覆盖；客户名单不沉淀（每次从数据重建）。

**PPT 产品的对应物（缺失）**：
- 当前每次引导都从零问受众/模式/风格，无"用户偏好记忆"。

**落地草案（分两步）**：
1. **领域档案**（立即做，低风险）：每领域一个 `profile.json`——沉淀已确认的偏好（B 模式老板版 vs 讲师互动版）、常用组件组合（如县域课件的 DC-01/02/03/04/17/20/08 组合）、术语口径（四力=品牌/渠道/场景/产品）。新任务先读档案，指纹核对（客户/主题/页数）后沿用；
2. **用户档案**（后续）：多用户时按人沉淀偏好（老板模式、字号习惯、是否要 notes），与领域档案叠加。

## 2. 验收自测清单（可勾选 + 参考值）

**客户分析的做法**：`验收自测清单.md`——每阶段 ☑/✗ 勾选项 + 参考值（如"合计 = 89210.5 ±1"、"参与计算行数 505"），5 分钟验货。

**PPT 产品的现状**：`quality-check.md` 是规则文本（"每个 slide 回答一个问题"），不是可勾选清单，无参考值。

**落地草案**：
1. 把质量检查升级为 `验收自测清单.md` 格式（勾选项 + 参考值）：
   - 参考值来源：本次 14 页课件验收沉淀的真实数据（品牌区 dark=2146/red=1987、溢出 0 处、COMPONENT_ID 0 个）；
   - 每页检查项：标题是结论不是标签、组件来源（复制源页 vs 重绘）、槽位替换完整性；
2. 清单与 `quality-check.md` 并存：规则解释"为什么"，清单回答"验什么、参考值是多少"。

## 3. 版本日志 = 实测失败模式记录

**客户分析的做法**：版本日志每版对应实测暴露的失败模式（v1.1.0 静默算错总数 → 双路径交叉验证；v1.1.1 虚构清洗 → 删除行清单；v1.3.1 状态字段推导成结论 → 禁止推导）。

**PPT 产品的现状**：HANDOFF.md 有"不要重复的错误"清单，但无版本-失败模式结构。

**落地草案**：
1. 建 `CHANGELOG.md`（仓库级）：每版记录"实测场景 + 暴露的失败模式 + 修复机制"；
2. 已可回填的三条（2026-08-14/15 实测）：
   - PowerPoint Agent 组件选择幻觉 → 防伪条款（图册 + 布局描述 + 图片未读取）
   - Agent 布局正确但改写组件语义 → 语义条款（布局看图、内容以卡片为准）
   - raw.githubusercontent.com 在 Agent 环境超时 → 文档记录 `?raw=true` URL 形式
3. 后续每轮实测/修复同步追加。

## 优先级

1. 验收自测清单（立即价值最高：下次 Build 直接用）
2. 领域档案（下次引导模式直接用）
3. CHANGELOG（低投入，先建骨架回填三条）
